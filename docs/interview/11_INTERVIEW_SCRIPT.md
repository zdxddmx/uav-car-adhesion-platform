# 11 面试口述稿（Interview Scripts）

> 四套口述稿：30 秒 / 1 分钟 / 3 分钟 / 8~10 分钟。工程师自然口吻，不要 AI 报告腔。结构：背景→职责→架构→难点→关键实现→一个代表性问题→结果→收获。所有数字都来自仓库，不编造性能数据。

---

## 1. 30 秒版（电梯 pitch）

> 「我实习在深圳维特智能，做的是无人机贴面小车平台里的车控侧。我用 STM32F103 写了一套四舵机四电机的固件：TIM2 四路 PWM 带四个 TB6612 电机，TIM5 两路硬件加两路软件 PWM 带四个舵机，PS2 手柄经 CH559 走 UART5 进来，500 毫秒失联自动停车。飞控那边我写了 height_commander 和 mylink_bridge 两个 PX4 模块。现在小车执行层和 PS2 链路有实物验证，飞控联调还在台架前阶段。」

## 2. 1 分钟版（自我介绍 + 边界）

> 「这个项目是无人机正压攀附平台，无人机负责送达和压紧，顶部一辆四轮转向小车负责贴面移动。我负责车控固件和 PX4 覆盖层两块。
>
> 车控是裸机前后台：主循环 10 毫秒轮询，TIM2 出 20 kHz 四路电机 PWM，TIM5 出 50 Hz 四路舵机 PWM——其中两路因为引脚被串口占了，我用『更新中断拉高、比较中断拉低』在 GPIO 上做了软件 PWM。控制源是 PS2 手柄，经 CH559 转成 UART5 的文本帧。安全上做了 500 毫秒失联保护、上电停车、J4 反装的方向修正。
>
> 飞控侧是两个 PX4 自定义模块加板级配置。说实话，这块只是源码整理，还没走完构建和实飞。我特别在意证据边界——哪些是实测、哪些是代码实现待回归、哪些还没做，我在仓库 README 和状态文档里都分开了，不会把『能编译』说成『已验证』。」

## 3. 3 分钟版（结构化深讲）

> 「先说背景：这个平台要解决的是无人机把检测载荷送到高空壁面并贴住工作的问题。无人机负责稳定和施加法向正压，小车负责贴面后的移动和转向。所以系统天然是两个控制器：飞控 PX4 和车控 STM32F103，中间要一条 UART 命令链路。
>
> 我的职责主要分两块。第一块是车控固件。分层是这样的：`car.c` 车辆层、`steering.c` 转向层、`servo.c` 和 `motor.c` 驱动层，输入层是 PS2。PS2 手柄经 2.4G 接收器到板载 CH559，CH559 转成 UART5 的 ASCII 帧，我这边 `sscanf` 解析出 8 个字节，只认 report ID 0x01。主循环 10 毫秒一次，把按键映射成 `car_forward/backward/turn` 这些车辆级调用。
>
> 硬件上有两个我觉得值得讲的点。第一是舵机：TIM5 只有 CH1、CH2 有能用的输出脚，CH3、CH4 的 PA2、PA3 被 USART2 占了，所以我让 CH3、CH4 只做内部比较时刻，在更新中断里把 PC5、PB0 拉高、在比较中断里拉低，用 GPIO 手搓了两路软件 PWM。第二是电机：PA15、PB3 是 JTAG 脚，我用 `AFIO_REMAP_TIM2` 把它们 remap 成 PWM，还针对 J4 反装做了 direction 修正，统一在配置表里处理。
>
> 安全上，我做了 500 毫秒失联保护，用『最近一次合法帧』计时而不是旧的『非零摇杆活动』计时——后者会把手松在中位误判成失联。飞控协议我也写了：USART2 上 11 字节帧、CRC-8/ATM 校验、DMA 环形接收、失步重同步，但当前运行固件刻意没启用，因为 USART2 还被 printf 占着做调试。
>
> 飞控侧是 PX4 覆盖层：height_commander 做 RC 开关触发的相对高度状态机，mylink_bridge 是个实验性的串口桥。mylink_bridge 这块我主动标了风险——它直接写执行器、没有 CRC 和超时，禁止实飞。
>
> 一个代表性问题：J4 电机方向反了。架空测试发现直行时一个轮子反向，我定位到是安装镜像，只在 `motor_config` 表里把 direction 改成 -1，没去上层打补丁。这让我形成了『方向、映射类问题集中在配置表解决』的习惯。
>
> 结果：Keil 全量重建 0 错误 0 警告，出了可烧录 HEX，小车执行层和 PS2 链路分阶段实测通过。收获是：学会了在资源受限的 F103 上做软硬件 PWM 混合、以及怎么诚实地管理证据边界。」

## 4. 8~10 分钟版（完整深挖，适合二面/技术面）

> 按「背景 → 职责 → 架构 → 难点 → 关键实现 → 代表性问题 → 结果 → 收获 → 主动暴露风险」展开，可在 3 分钟版基础上逐段展开：

**背景（1 分钟）**
> 无人机正压攀附 + 顶部四轮转向小车。为什么这个组合：悬停耗电且不稳定，贴面后由小车承担移动，无人机只管压紧。两个控制器职责清晰分开。

**架构（2 分钟）**
> 画分层：输入层（PS2/CH559/UART5）→ 应用层（main 的 ps2 状态机）→ 车辆层 car.c → 驱动层 steering/servo/motor → 硬件 TIM2/TIM5/TB6612。强调「只有底层驱动能碰 TIM CCR 和 GPIO」，所以换控制源不用重写驱动。再画时钟树：HSE 16M ÷2 → PLL ×9 → 72M，APB1 定时器 ×2。

**难点 1：舵机软硬件 PWM 混合（1.5 分钟）**
> TIM5 资源、引脚冲突、软件 PWM 的实现和抖动风险、ISR 精简、错峰启动。

**难点 2：失联保护与计时语义（1 分钟）**
> 为什么用「合法帧时间戳」而不是「非零活动」，三层 failsafe（PS2/flight_comm/rc_control）。

**关键实现：11 字节 CRC8 协议（1.5 分钟）**
> 帧格式、CRC-8/ATM 参数、DMA 环形接收、失步重同步、`FLIGHT_COMM_ENABLE_CAR_OUTPUT` 安全门、为什么当前没启用（USART2 被 printf 占用）。

**飞控侧（1 分钟）**
> height_commander 状态机 + NED、mylink_bridge 危险路径主动承认。

**一个代表性问题（1 分钟）**
> J4 方向反装 → 定位 → 配置表修正 → 复盘「方向问题不散落上层」。

**结果与边界（1 分钟）**
> 0 error 0 warning、HEX SHA256、已实测/待回归/未完成三分法。

**收获（30 秒）**
> 资源受限下的寄存器级掌控、前后台并发与竞态意识、以及「证据边界」的职业习惯。

## 5. 口述时的「红线提醒」

1. **不编数据**：不报「抖动 XX μs」「跑 XX m/s」「PID 调好了」这类仓库没有的数字。
2. **主动说边界**：每次提到飞控、蟹行、编码器 PID、90° 转角，紧跟一句「这块还没实测/没启用」。
3. **把「未启用」讲成主动决策**：不是「不会」，是「这个阶段裸机前后台更合适 + 安全门没放开」。
4. **报错要具体**：能背出 `J4 direction=-1`、`CRC-8/ATM poly 0x07`、`50 Hz = PSC71/ARR19999` 这几个数字。
